# M14 — Reliability & performance laboratory

## Title / Context
Reliability & performance laboratory. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: N01/N02/N04/N06 load thresholds and functional integrity under faults. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
k6, controlled fault injection. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M13. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Environment manifest, warmup/sample, trace/error denominators; retry/jitter/PSP breaker; DLQ replay; Kafka comparative projection.

## Functional Requirements
N01/N02/N04/N06 load thresholds and functional integrity under faults. Связанные требования: F18, N01, N04, N06.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Raw load report, crash evidence, Kafka offsets/rebalance comparison. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M14/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
20VU read p95≤300ms command≤500ms saga≤5s healthy; recovery100 bookings≤120s.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: N01/N02/N04/N06 load thresholds and functional integrity under faults. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
120s broker outage, killed consumer after commit, partition, delayed PSP, poison payload. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain percentile vs average, coordinated omission, recovery limits. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
Record failures and tuning impact; no fabricated charts/benchmark numbers. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Stress until saturation, queue backpressure sizing. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
