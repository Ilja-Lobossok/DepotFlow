# M13 — Contracts, migrations & CI

## Title / Context
Contracts, migrations & CI. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F17 backward-compatible optional field and independent build scripts. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
Compatibility, CI DAG, supply chain. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M12. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Provider/consumer fixtures, breaking diff gate, expand/contract migrations, image digest/SBOM scans.

## Functional Requirements
F17 backward-compatible optional field and independent build scripts. Связанные требования: F17.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
CI workflow, PR review, v1/v2 migration exercise. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M13/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
Old consumer passes additive schema; breaking change blocked; previous migration upgrade works.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F17 backward-compatible optional field and independent build scripts. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Shared schema change ignored by naive path filter; old consumer deployment. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain enum evolution and meaning change that schema diff misses. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
CI executes real checks, not echo success; changed contract rebuilds impacted consumers. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Jenkins pipeline comparison lab. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
