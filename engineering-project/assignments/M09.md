# M09 — Warehouse physical workflow

## Title / Context
Warehouse physical workflow. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F09/F10 operator depot enforcement, serial inspection, overrun incident. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
Fencing, frontend forms. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M08. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Fulfillment own jobs, projection+authoritative handover claim, all-assets return, damage quarantine.

## Functional Requirements
F09/F10 operator depot enforcement, serial inspection, overrun incident. Связанные требования: F09, F10.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Warehouse API, handover/return UI, recovery incident scenario. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M09/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
Cancel/handover exactly one winner; double return one report; absent asset not handed over.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F09/F10 operator depot enforcement, serial inspection, overrun incident. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Claim response lost; operator restart; return arrives before handover event. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain why handover claim has no automatic timeout release. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
Physical actions audited; no silent future reservation deletion. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Partial return extension. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
