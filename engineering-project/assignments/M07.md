# M07 — Sandbox billing & confirmation saga

## Title / Context
Sandbox billing & confirmation saga. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F06 successful auth+commit confirms; cost snapshot used. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
Saga, payment idempotency. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M06. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Billing sandbox adapter auth/query/void/capture/refund; Booking durable orchestration with deadlines.

## Functional Requirements
F06 successful auth+commit confirms; cost snapshot used. Связанные требования: F06.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Billing models/ledger, saga transitions, sandbox fault controls. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M07/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
Unknown reconciled by same key; expired hold never committed; one auth.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F06 successful auth+commit confirms; cost snapshot used. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
PSP succeeds then response lost; broker outage while hold expires. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Trace confirmation; explain compensation not DB rollback. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
All forward/late event fixtures pass; no real money/card data. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
PSP circuit breaker experiment. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
