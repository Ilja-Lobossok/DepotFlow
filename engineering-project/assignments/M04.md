# M04 — Inventory integrity

## Title / Context
Inventory integrity. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F03/F13/F16 queries, conflict maintenance and asset lifecycle. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
SQL locks/MVCC, PostgreSQL ranges. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M03. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Inventory own DB; asset/depot/maintenance models; atomic qty allocation; GiST overlap invariant; If-Match.

## Functional Requirements
F03/F13/F16 queries, conflict maintenance and asset lifecycle. Связанные требования: F03, F13, F16.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Inventory migration, ERD, contention report, query plans. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M04/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
100 simultaneous overlapping requests on one unit produce1hold; all-or-nothing qty5.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F03/F13/F16 queries, conflict maintenance and asset lifecycle. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Two concurrent holds/maintenance; DB deadlock abort/retry bounded. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain isolation and exclusion; inspect real constraints and plan. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
No overlapping active allocations; stale edit412; migration upgrade test. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Serializable vs Read Committed contention experiment. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
