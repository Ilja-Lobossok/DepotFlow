# M17 — IaC, backup & restore

## Title / Context
IaC, backup & restore. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F20/N10 isolated restore; state/provider reconcile across differing backup cuts. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
OpenTofu, Ansible, storage/reconciliation. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M16. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Mandatory local isolated VM/state simulation; optional AWS sandbox only after user spending authorization; snapshots, encryption and restore.

## Functional Requirements
F20/N10 isolated restore; state/provider reconcile across differing backup cuts. Связанные требования: F20, N10.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
IaC plan, idempotent Ansible report, backup inventory, timed restore. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M17/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
Second Ansible run unchanged; restore≤30min fixture, delta known; no credentials in state repo.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F20/N10 isolated restore; state/provider reconcile across differing backup cuts. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Missing volume, corrupt backup, mismatched service restore points. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain resource graph, drift and RPO vs RTO; estimate cloud cost with sourced assumptions. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
Clean recovery proves allocation/ledger counts and reports unrecoverable delta. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
PITR coordinated recovery watermark. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
