# M01 — Lab foundations

## Title / Context
Lab foundations. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: DNS/ports explained; clean machine instructions; each image independently builds. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
Linux, networking, Docker, Git. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
none. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Build isolated lab; pin versions; seven empty service build boundaries; dependency Compose specification; no business implementation supplied.

## Functional Requirements
DNS/ports explained; clean machine instructions; each image independently builds. Связанные требования: A03/A05 platform acceptance.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Architecture skeleton, version lock, resource inventory, environment README. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M01/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
One independent build per service; no shared DB role; dependency health evidence.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: DNS/ports explained; clean machine instructions; each image independently builds. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Kill local lab process; distinguish socket absence from health response. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain namespaces, loopback, TLS; show git diff and reproducible clean start. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
Lab footprint report; one nonroot image runs; documentation covers every command. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Native image comparison with measured memory. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
