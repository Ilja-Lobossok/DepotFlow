# M12 — Observability & incident diagnosis

## Title / Context
Observability & incident diagnosis. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F15/N05 correlate delayed saga with blocked adapter and queue age. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
Tracing, metrics/logs, SLO. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M11. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
OTel context over HTTP/AMQP; Prometheus histograms; Grafana dashboards; Loki logs; Tempo traces.

## Functional Requirements
F15/N05 correlate delayed saga with blocked adapter and queue age. Связанные требования: F15, N05.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Dashboard JSON, alert rules, redacted incident report. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M12/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
Trace links across all saga edges; no high-cardinality booking metric label.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F15/N05 correlate delayed saga with blocked adapter and queue age. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Poison event, slow SQL, missing context on async hop. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Identify bottleneck from telemetry without reading implementation first. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
Reviewer diagnoses injected incident in15min with retained evidence. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Tail sampling cost comparison. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
