# M02 — Identity & tenant boundaries

## Title / Context
Identity & tenant boundaries. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F01/N03 role matrix against two tenants; token audience/expiry tests. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
OIDC, JWT, RBAC. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M01. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Integrate Keycloak PKCE; Tenancy memberships; owner checks on every endpoint; JWT never in localStorage.

## Functional Requirements
F01/N03 role matrix against two tenants; token audience/expiry tests. Связанные требования: F01, N03.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Tenancy API, auth matrix, threat model baseline. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M02/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
401 invalid token;403 forbidden own command;404 foreign object; mutations revoke immediately.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F01/N03 role matrix against two tenants; token audience/expiry tests. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
IdP/JWKS outage and revoked membership during form submit. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain issuer vs audience, authentication vs authorization. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
Role matrix automated; no cross-tenant cache/event leakage. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
BFF session comparison. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
