# M06 — Messaging & contract gates

## Title / Context
Messaging & contract gates. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: Reserve command→HoldCreated facts, delivery identifiers and version rules. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
AMQP, event schemas, outbox/inbox. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M05. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
RabbitMQ exchanges/queues/ACL; confirms+mandatory, ack after DB; AsyncAPI per service; contract fixtures.

## Functional Requirements
Reserve command→HoldCreated facts, delivery identifiers and version rules. Связанные требования: A03/A05 platform acceptance.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Publisher/consumer tests, topology spec, fixture compatibility checks. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M06/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
At least10 duplicate deliveries yield one effect; poison schema→DLQ with original metadata.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: Reserve command→HoldCreated facts, delivery identifiers and version rules. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Crash after confirm before mark, crash after commit before ACK, unroutable publish. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain confirms vs ack; no broker delivery equals transaction success. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
No lost committed outbox in induced crashes; publish/inbox metrics. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Compare Redis Streams ownership/replay. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
