# M10 — Settlement & refunds

## Title / Context
Settlement & refunds. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F11/F12 late fee, damage, refunds and sandbox webhook signature. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
Financial invariants, reservations. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M09. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Capture≤auth; pending_refund reservation; immutable ledger; void remainder; manual review.

## Functional Requirements
F11/F12 late fee, damage, refunds and sandbox webhook signature. Связанные требования: F11, F12.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Ledger audit tests, refund UI, reconciliation operator evidence. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M10/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
15000 auth example yields8500 capture; two full refunds never overrefund.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F11/F12 late fee, damage, refunds and sandbox webhook signature. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Capture succeeded then transport timeout; refund webhook duplicates and out-of-order. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain pending refund vs recorded refund and available remainder. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
Ledger sums and provider outcomes agree for100 scripted cases. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Deposit-only capture and progressive settlement. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
