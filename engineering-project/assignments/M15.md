# M15 — Production-like Kubernetes & security

## Title / Context
Production-like Kubernetes & security. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: N07 ingress only; DB denied to other owner; scale Inventory2 replicas respects invariant. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
Docker, networks, Kubernetes, Helm. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M14. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
kind/k3d seven Deployments, own DBs, resource limits/probes, network policies, TLS; secrets nonrepo.

## Functional Requirements
N07 ingress only; DB denied to other owner; scale Inventory2 replicas respects invariant. Связанные требования: N07, N11.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Helm charts, measured resources, threat tests, topology capture. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M15/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
Old pods drain30s; own migration job; wrong DB role denied; rollout maintains invariants.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: N07 ingress only; DB denied to other owner; scale Inventory2 replicas respects invariant. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Broker outage must not liveness-restart services; rolling update during hold. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain StatefulSet is not HA, PVC/backups, readiness gates. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
Clean local cluster deploy and security matrix pass; lab overhead recorded. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Three-node quorum broker fault lab. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
