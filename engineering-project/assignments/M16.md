# M16 — Independent delivery & rollback

## Title / Context
Independent delivery & rollback. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F19 release Notification without six core image changes. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
CI/CD, rollout, signed digest. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M15. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Deploy per-service digest after smoke/contract/migration checks; environment gate; previous image retention.

## Functional Requirements
F19 release Notification without six core image changes. Связанные требования: F19, N08.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Release pipeline and rollback evidence with before/after digests. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M16/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
Notification-only diff; failed update leaves working pods; revert image retains schema compatibility.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F19 release Notification without six core image changes. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Bad readiness image, incompatible required field, failed migration. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain why destructive migration cannot be rolled back by image rollback. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
Actual release/rollback recorded, previous consumer works expanded schema. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Canary traffic and automated rollback thresholds. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
