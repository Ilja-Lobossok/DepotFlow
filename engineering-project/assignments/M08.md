# M08 — Cancellation & races

## Title / Context
Cancellation & races. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F08/F18 all partial states cancel; terminal does not resurrect. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
Compensation, event ordering. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M07. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Cancellation tombstone, Inventory release idempotent, late auth void, deadline reconciliation worker.

## Functional Requirements
F08/F18 all partial states cancel; terminal does not resurrect. Связанные требования: F08, N02.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Race tests with deterministic barrier; reconciliation runbook. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M08/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
100 runs each race: no cancelled active allocation/net captured; completion≤120s after recovery.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F08/F18 all partial states cancel; terminal does not resurrect. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Cancel vs commit, reserve after release, late Authorized after Failed. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain why timeout cannot mark cancellation complete. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
Race matrix and actual owner-state proofs retained. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
Property-based state machine exploration. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
