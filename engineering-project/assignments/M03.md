# M03 — Catalog & pricing

## Title / Context
Catalog & pricing. Самостоятельный инженерный этап DepotFlow. Ценность в реальной работе: F02/F04 with25h/qty2 example and rate change. Ориентир трудоёмкости 15–40 focussed sessions по1–3h (архитектура/restore может больше); это planning assumption, не обязательный срок и не обещание результата.

## Learning Objectives
Java, REST, SQL, unit testing. Уметь объяснить причину выбранного механизма, альтернативу и ограничение до реализации.

## Prerequisites
M02. Прочитать product/business-processes.md и соответствующие service passports/контракты. Перед практикой объяснить незнакомые термины; не копировать готовое бизнес-решение.

## Technical Requirements
Catalog versioned rates, immutable quote, OpenAPI schema validation; integer money only.

## Functional Requirements
F02/F04 with25h/qty2 example and rate change. Связанные требования: F02, F04.

## Constraints
Семь независимых владельцев данных; никакого shared database access или подмены backend+worker. Бизнес-код пишет студент. Все retries ограничены, деньги integer, состояния durable, tenant checks server-side. Только sandbox, синтетические данные, isolated lab. Не менять личные VM/credentials/main/remote для выполнения учебного этапа.

## Expected Deliverables
Catalog image+migrations, price tests, fixture, API evidence. Дополнительно: README воспроизведения с местом запуска каждой команды и смыслом аргументов, evidence/M03/manifest.json (commit, image digests, CPU/RAM, dataset seed, UTC time), raw test outputs, ADR если изменились границы.

## Acceptance Criteria
25h quote calculates10000 rental+20000 deposit; expired quote422.

Для каждого связанного F/N требования повторить соответствующий Given/When/Then. Показать независимый запуск теста и состояние после операции, не только HTTP response. Результат = pass/failed/blocked с ссылкой на evidence; непроверенное не pass.

## Testing Scenarios
Positive: F02/F04 with25h/qty2 example and rate change. Negative: forbidden tenant/role, malformed body, unavailable required owner, conflicting operation. Boundary: zero/one/max qty, exact expiry and interval endpoints where relevant. Запустить unique-key повтор и stale version; fixtures в reviews/scenarios.json. Unit tests не заменяют DB/transport experiments.

## Failure Scenarios
Catalog DB timeout during quote; ensure no booking created. Записать trigger → observed state → recovery → invariant checks. Рестарт контейнера должен сохранять committed state. Отказ воспроизводится в изолированной среде без удаления чужих данных.

## Review / Audit
Explain rate snapshot and UTC/DST rounding. Reviewer выбирает один негативный сценарий сам, читает transaction boundary, проверяет ownership credentials и контракт. Нельзя пройти этап только по screenshot/green checkbox.

## Definition of Done
All quote bounds plus tenant tests pass; independent service build. Deliverables доступны, acceptance evidence со стабильными IDs, review замечания resolved или explicit limitation, clean-start инструкции повторены. Правила Ready/Done в operations/engineering-process.md.

## Bonus / Advanced
gRPC quote lab benchmark. Bonus после обязательных проверок; записать ADR и сравнение, не добавлять инструмент без сценария.
