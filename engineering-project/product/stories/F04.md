# F04 — Котировка

## Context & business goal
Как customer, хочу: Получить неизменяемую цену.

## Preconditions
F03; период 1h..30d, начало ≥ now+1h. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Quote expires after 15 min; days=ceil(duration/24h); quantity multiplied.

## Alternative scenarios
Quote expired -> refresh with explicit consent if amount changes.

## Error scenarios
Вход содержит decimal money or negative duration ->422. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
Given 25 h, qty2, rate2500, deposit10000 per unit; Then days2, rental10000, deposit20000, total authorization30000.

Записать автоматизированный тест с ID F04, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F03; этап M03; экраны: quote,checkout. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
