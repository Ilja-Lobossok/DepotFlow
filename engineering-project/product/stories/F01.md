# F01 — Доступ организации

## Context & business goal
Как org_admin, хочу: Разделить данные компаний.

## Preconditions
OIDC session; active organization. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Пригласить участника; назначить одну роль и при необходимости depot.

## Alternative scenarios
Отозвать membership; следующий command запрещён.

## Error scenarios
Чужой org или depot -> 404/403. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
Given A/B; When member A GET booking B; Then 404 и тело без PII. Revocation запрещает команды сразу после authoritative check, чтения ≤60 s.

Записать автоматизированный тест с ID F01, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
M01; этап M02; экраны: login,team. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
