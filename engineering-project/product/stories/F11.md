# F11 — Завершение оплаты

## Context & business goal
Как customer, хочу: Списать аренду и вернуть остаток.

## Preconditions
F10; valid authorization. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Capture rental+late+damage within authorized bound; remainder void; ledger persists.

## Alternative scenarios
Provider unknown -> reconciling and operator alert.

## Error scenarios
Overdeposit total -> manual_review; never overcapture. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
Given authorized15000, rental5000, late2500, damage1000; Then capture8500 and void remaining6500, captured-refunded=8500.

Записать автоматизированный тест с ID F11, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F10; этап M10; экраны: billing,booking. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
