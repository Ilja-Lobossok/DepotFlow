# F20 — Резервное копирование

## Context & business goal
Как engineer, хочу: Восстановить данные с измеренным ущербом.

## Preconditions
M15; synthetic workload. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Backup all owned stores and record cutover times; restore to isolated namespace; reconcile saga/provider.

## Alternative scenarios
Unequal backup timestamps -> report and recovery queue.

## Error scenarios
Restore into active prod namespace -> forbidden. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
When restore controlled checkpoint; Then known booking counts, ledger balance and allocation invariants match checkpoint; measured RTO≤30min and snapshot RPO≤24h.

Записать автоматизированный тест с ID F20, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
M15; этап M17; экраны: operations. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
