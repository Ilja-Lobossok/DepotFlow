# F06 — Подтверждение аренды

## Context & business goal
Как customer, хочу: Получить договор после авторизации.

## Preconditions
F05; PSP sandbox. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
HoldCreated -> authorize; Authorized -> commit; Committed -> confirmed.

## Alternative scenarios
Transient faults leave pending/reconciling; customer sees status.

## Error scenarios
Expiry before commit -> release and void; never confirm expired hold. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
Given authorization succeeds and allocation commits; Then one confirmed booking, one active allocation, one authorization; 10 duplicate events change none of these counts.

Записать автоматизированный тест с ID F06, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F05; этап M07; экраны: pending,booking. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
