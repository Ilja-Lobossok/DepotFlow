# F17 — Контракты и эволюция

## Context & business goal
Как engineer, хочу: Поставлять сервисы независимо.

## Preconditions
M06; v1 consumers. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Add optional field; provider and old consumer contract suite run.

## Alternative scenarios
Breaking meaning -> v2 route/event, overlap deployments.

## Error scenarios
Required field removal or enum narrowing -> CI failure. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
Given old consumer fixture; When optional field added; Then both deserialize; breaking fixture rejected before release.

Записать автоматизированный тест с ID F17, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
M06; этап M13; экраны: contracts. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
