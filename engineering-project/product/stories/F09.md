# F09 — Складская выдача

## Context & business goal
Как operator, хочу: Передать конкретные assets клиенту.

## Preconditions
F06; same depot; now in pickup window start-1h..end. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Claim handover atomically in Booking then Fulfillment records act.

## Alternative scenarios
Lost response: query claim, resume same job, never release automatically.

## Error scenarios
Missing allocation, revoked operator, cancellation won ->409/403. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
When cancel and handover claim race; Then exactly one wins. Double handover returns original act; different payload ->409.

Записать автоматизированный тест с ID F09, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F06; этап M09; экраны: warehouse,handover. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
