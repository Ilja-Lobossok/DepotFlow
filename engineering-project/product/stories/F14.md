# F14 — Уведомления и realtime

## Context & business goal
Как customer, хочу: Увидеть изменения без повторного checkout.

## Preconditions
F06; Notification running. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Durable notification, SSE with cursor, email sink retry.

## Alternative scenarios
SSE disconnected -> reconnect then HTTP snapshot; email fail does not fail booking.

## Error scenarios
Cross-tenant SSE cursor ->404; unknown cursor -> fresh snapshot. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
Given confirmed event duplicated; Then one UI notification; SSE reconnect recovers latest state; email failure leaves confirmed.

Записать автоматизированный тест с ID F14, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F06; этап M11; экраны: notifications,booking. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
