# F07 — Идемпотентность команд

## Context & business goal
Как customer, хочу: Безопасно повторить потерянный ответ.

## Preconditions
F01; Idempotency-Key. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Store request hash and durable response per org+subject+route+key 24h.

## Alternative scenarios
Same hash returns same resource/status; processing ->202.

## Error scenarios
Same key different body ->409 idempotency_mismatch. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
When retry 20 times after response loss; Then one booking and one operation; tenant B may reuse same key independently.

Записать автоматизированный тест с ID F07, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F01; этап M05; экраны: checkout. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
