# F13 — Ремонт

## Context & business goal
Как operator, хочу: Блокировать неисправный экземпляр.

## Preconditions
F01; assigned depot. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Create maintenance allocation for non-rented asset; complete repair explicitly.

## Alternative scenarios
Future reservations conflict -> reject and show affected booking IDs for dispatcher.

## Error scenarios
Already handed_over ->409; cannot delete existing bookings. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
When maintenance period overlaps a committed booking; Then409 and no maintenance insert; after successful repair new hold is permitted.

Записать автоматизированный тест с ID F13, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F01; этап M04; экраны: fleet,maintenance. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
