# F08 — Отмена до выдачи

## Context & business goal
Как customer, хочу: Освободить резерв и деньги.

## Preconditions
F06; pending or confirmed, not handed over. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Record cancellation intent under booking lock; saga releases allocation and voids authorization.

## Alternative scenarios
Late authorized event triggers void even after cancellation.

## Error scenarios
Handover claimed or handed_over ->409 cannot_cancel. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
When cancel races allocation commit; Then terminal cancelled eventually has no active allocation and net captured0; timeout alone is not cancelled completion.

Записать автоматизированный тест с ID F08, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F06; этап M08; экраны: cancel,booking. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
