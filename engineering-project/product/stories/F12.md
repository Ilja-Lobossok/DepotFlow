# F12 — Возврат списанных средств

## Context & business goal
Как finance, хочу: Исправить ошибочное списание.

## Preconditions
F11; finance role; captured>refunded. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Reason mandatory; idempotent refund ≤ remaining captured; webhook verifies result.

## Alternative scenarios
Timeout queries PSP before retry.

## Error scenarios
Customer role ->403; refund over remainder ->422. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
When two concurrent full refunds; Then total refunded ≤ captured and one succeeds; second conflicts.

Записать автоматизированный тест с ID F12, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F11; этап M10; экраны: billing,refund. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
