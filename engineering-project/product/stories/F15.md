## Context & business goal
Как org_admin, хочу: Объяснить изменения процесса.

## Preconditions
F01; commands/events exist. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Timeline with source event and correlation; auth decisions audit separately.

## Alternative scenarios

## Error scenarios
Secrets, tokens, full email never written to telemetry. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
When investigate failed booking; Then actor, before/after state, correlation and saga phase are recoverable; timeline rows unique by source event.

Записать автоматизированный тест с ID F15, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
