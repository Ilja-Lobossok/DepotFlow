# F03 — Поиск доступности

## Context & business goal
Как customer, хочу: Найти модель на срок.

## Preconditions
F02; depot active. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Выбрать depot, start/end, quantity; фильтр категории, cursor pagination.

## Alternative scenarios
Нет единиц -> empty state; Redis down -> SQL.

## Error scenarios
start>=end, quantity вне 1..5 ->422. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
When 26 models with page limit 25; Then second cursor returns last item without duplicate. Availability never guarantees allocation.

Записать автоматизированный тест с ID F03, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F02; этап M04; экраны: catalog,availability. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
