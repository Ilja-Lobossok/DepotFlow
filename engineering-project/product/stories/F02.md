# F02 — Каталог и тариф

## Context & business goal
Как org_admin, хочу: Управлять арендным предложением.

## Preconditions
F01; модель принадлежит tenant. Выполнить проверку auth/session/tenant до доступа к данным. Пользовательские команды идут через gateway, service credentials не заменяют customer identity.

## Expected behavior / Main scenario
Создать model и rate в EUR minor units; заменить rate новым version.

## Alternative scenarios
Deactivate model скрывает новые quotes, не ломает существующие.

## Error scenarios
Нулевая/отрицательная стоимость или inactive model -> 422. UI показывает стабильный problem code, correlation ID и разрешённое действие. Не раскрывает чужие идентификаторы или stack trace.

## Acceptance criteria
Given rate 2500; When rate changes to 3000 after quote; Then existing quote uses 2500 until expiry.

Записать автоматизированный тест с ID F02, fixture version и фактическим результатом. Снимок UI — дополнение к проверке состояния, а не доказательство транзакции.

## Dependencies and implementation task
F01; этап M03; экраны: catalog,rate. Отдельный PR с review контракта и failure evidence. Для повторных команд и событий действуют общие правила contracts/README.md.
